# Knowledge Governance

Use this layer to decide whether a knowledge source is authoritative, current,
and applicable to the task.

Read `information-security-policy.md` first whenever the task handles credentials,
customer data, project artifacts, repositories, or external transmission.

Read in this order when expected behavior or source authority matters:

1. `source-registry.md`
2. `authority-matrix.md`
3. `conflict-resolution.md`
4. `freshness-policy.md`
5. `knowledge-metadata-standard.md`
6. `change-approval-policy.md`

Use `decision-rules/` for QA prioritization, escalation, and release reasoning.

Record every approved Skill or Knowledge change in
`change-approval-register.md`. Approval evidence belongs in the register, not in
OpenAI Skill frontmatter.
